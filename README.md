# DSH RedTeam 模式

DSH RedTeam 模式运行在 DeepSeek Harness（DSH）里，用来组织红队测试流程。
给它一个已授权的靶标单位名称，它会按“信息收集 → 资产梳理 → 漏洞发现 →
漏洞利用 → 内网信息收集 → 内网渗透”的顺序安排智能体，并把过程、证据和
结果记录在本机事实库中。

> 仅限已获授权的攻防演练、渗透测试和安全研究。未授权的扫描、探测、入侵
> 或数据获取均属违法。
>
> 本项目是智能体编排、事实库和报告工具，不包含、也不提供绕过模型安全
> 围栏的能力，包括所谓“破甲”、越狱、绕过审核或规避模型安全策略。
> 智能体仍受 DSH 和所用模型的安全策略约束。仓库不内置攻击工具或工具
> 二进制，工具由使用者自行准备。

## 主要功能

- **角色分工**：主会话负责计划、派活和汇总，信息收集、资产梳理、漏洞发现、
  漏洞利用、内网信息收集、内网渗透六个执行角色各自完成具体工作；执行角色
  是叶子节点，不再向下委派。
- **本机事实库**：资产、端口、漏洞、凭据、访问会话、WebShell、隧道、得分、
  证据截图和 POC 都写入本机 SQLite，面板和报告使用同一份数据。
- **单资产漏洞发现**：按 surface / web / auth / cve / app 五项逐个资产检查，
  批量扫描只作为候选，不代替单资产深挖；未完成的资产不能直接收口。
- **内网覆盖度**：主机拿到权限后继续跟踪文件、凭据、提权、Web、数据库和
  横向移动，未完成项会持续回到下一步队列。
- **得分与报告**：按内置得分规则记录命中、权限和证据，报告给出资产证明、
  得分汇总、凭据汇总和可复现步骤。
- **控制台**：右侧栏提供态势、资产、成果、报告、资源五个分区，共 9 个页面；
  面板跟随当前会话绑定的靶标，多会话并行时不会看串。
- **知识与技能**：随包提供 41 个技能，覆盖信息收集、单资产深挖、漏洞验证、
  内网、隧道和报告；技能缺工具或环境变量时会直接说明，不提供自动安装。

目前包含 63 个工具、41 个技能和 7 个角色。

## 安装

```sh
dsh plugin --profile web add \
  https://github.com/Jueze-2019/dsh-redteam-mode/releases/download/v0.16.1/dsh-redteam-mode-0.16.1.tgz
```

安装后重启一次 `dsh web`，在助手栏选择“红队模式”。

前置条件：

- DSH 能正常运行 `dsh web`
- Node.js ≥ 22.13
- 建议在专供演练的 Kali 虚拟机中运行

## 使用方式

1. 在红队模式会话中发送已授权的靶标单位名称。
2. 先运行 `redteam_preflight`，确认技能、工具和环境变量是否齐全。
3. 信息收集角色整理资产，资产梳理角色给出优先级和攻击面。
4. 主会话按单个资产派发漏洞发现任务；确认漏洞后再派漏洞利用。
5. 进入内网后，由内网信息收集角色整理地图，内网渗透角色继续做凭据复用、
   提权、数据证明和必要的横向移动。
6. 在面板中查看资产、成果、得分和资源，最后生成报告。
7. 交付前检查清理台账，确认上传的文件、账号和隧道已经处理。

## 控制台

右侧控制台包含：

- **态势**：当前靶标、资产、得分和会话概览
- **资产**：资产测绘、C 段、域名、Web、发现时间和测试队列
- **成果**：漏洞战果、得分目标、命中记录和证据
- **报告**：按阶段查看成果，生成可复现的交付报告
- **资源**：WebShell、内网隧道、凭据、访问会话、攻击文件和知识库

## 数据与运行

业务数据默认写入 `$DSH_HOME/redteam/`，不包含遥测、上报或云端同步。
工具和运行时由使用者自行准备；仓库只提供插件、技能、预设和事实库逻辑。
