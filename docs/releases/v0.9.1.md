技能库显示可用性状态；信息收集提示词补内网章节（**必须用 gogo / fscan**）；修部署脚本用旧预设覆盖用户预设的问题。

## 技能库：每个技能带可用性状态

技能能列出来 ≠ 能跑。新增状态徽章（**可用 / 不可用 / 未知**），判定五个维度：

| 维度 | 判什么 |
| --- | --- |
| 技能文件 | 文件是否存在 |
| 正文 | 能否加载出来 |
| 必需环境变量 | `os.environ["FOFA_KEY"]` / `process.env.X` / `${X:?}`；**带默认值的 `os.environ.get("X","…")` 不算必需**（否则会把能用的技能误判成坏） |
| 本机路径 | 正文引用的 `$DSH_HOME/redteam/toolkit/...`、`~/.local/bin/...` 是否真实存在 |
| 基础设施占位符 | `<你的VPS_IP>` 这类没填的 |

界面上：三色徽章 + 缺口直接列在条目下（如「缺环境变量 FOFA_KEY」）+ 详情页有「缺口」「需要你提供什么」+ 「只看不可用/未知」+ 「重查可用性」（跳过 30 秒缓存）。

**判定逻辑只有一份实现**：`packages/redteam-store/lib/skill-availability.js`。`redteam_preflight`（智能体侧）与面板「技能库」（用户侧）调的是同一份 —— 面板上说不可用的，智能体预检也会说不可用，不会出现两套结论。

## 信息收集：内网必须用 gogo + fscan

`recon` 角色提示词现在明确区分两种作战场景，并写死内网用哪两个技能：

- **先看隧道**：`redteam_sessions` / `redteam_tunnel_list` 取 `status=active` 且 `legit=true` 的隧道与真实监听地址；**没有隧道就没有内网收集的前提**——如实回报，而不是手搓探测脚本硬上。
- **gogo 铺面**：`gogo -p <网段> --proxy socks5://<隧道> -o runs/gogo-<网段>.json` —— 存活 / 端口 / 服务 / 指纹 / 关键信息（title、证书、JWT、邮箱、身份证命中），这一步决定"内网有多大"。
- **fscan 打点**：`fscan -h <网段> -socks5 <隧道> -o runs/fscan-<网段>.txt` —— 弱口令 / 未授权 / 高危漏洞（MS17-010、SMBGhost、Redis…）的结果**作为漏洞发现的线索记进该资产 `surface`**，收集角色自己不下结论、不做利用。
- **网段要挖全**：从已控主机的 `ip route` / `arp -a` / DNS 与域信息 / `hosts` / `known_hosts` / 数据库连接串 / 日志里的内网地址入手，配合 gogo/fscan 结果把 `10.x`、`172.16-31.x`、`192.168.x` 的可达性摸出来；**每发现一个新网段就再跑一轮**，直到没有新网段、没有新存活。
- 逐条落库（`tool=gogo|fscan`，内网地址自动 `scope=internal`），隧道参数保留在实际命令里供报告复现。

同时明确写入预设：**内网不要用 nmap 一台台扫**，先用 gogo 铺面再打点。
