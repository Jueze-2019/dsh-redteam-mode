# v0.10.0 — 工具配齐、技能补齐、首次使用引导

> 主题：**从"有骨架"到"开箱即用"**。让用户第一次进红队模式时，环境自动配齐、缺口一次性说清；
> 让六个角色真正用上本机已有但此前调不到的工具。

## 一、技能从 13 个补到 23 个（全部对应真实二进制）

原先 13 个技能只覆盖了本机可用工具的一小部分——`nuclei`、`sqlmap`、`ffuf`、`hydra`、`hashcat`、
`impacket`（61 个命令）、`chisel`、`frp`、`msfconsole` 都装了但**没有技能，智能体调不到**。
本次按五个类别补齐 10 个技能：

**新增技能**

| 技能 | 角色 | 补上的能力缺口 |
| --- | --- | --- |
| `nuclei-scan` | vuln-scan | **漏洞发现类此前没有任何可用技能**，nuclei（13,742 个模板）无处可用 |
| `dir-bruteforce` | vuln-scan | 目录/备份/配置文件爆破（feroxbuster / ffuf / dirsearch / gobuster）——实战里大部分入口来源 |
| `unauth-exploit` | vuln-scan | 暴露服务直取：Redis / MySQL / MSSQL / ES / Docker / MongoDB / SMB 空会话 / Jenkins / JDWP |
| `credential-attack` | exploit | **此前完全没有弱口令与凭据链路**：hydra 在线 + hashcat/john 离线 + 凭据复用 |
| `shell-handler` | exploit | **此前没有会话 handler**：MSF `multi/handler`、`web_delivery`、nc/socat、tmux 常驻 |
| `recon-pipeline` | recon | ProjectDiscovery 流水线：subfinder → dnsx → naabu → httpx |
| `chisel-tunnel` | internal | 隧道第二通道：HTTP/WebSocket，最易穿透出网限制 |
| `frp-tunnel` | internal | 隧道第三通道：长期稳定 + 端口映射给用户直接用 |
| `lateral-movement` | internal | **横移与提权此前完全空白**：Impacket（PtH / WMI / DCOM / Kerberos / secretsdump / DCSync） |
| `redteam-setup` | plan | 首次使用引导（见第三节） |

**已有技能增强**：`fscan-intranet` / `gogo-intranet` / `vps-reverse-shell` 的 VPS 地址从硬编码占位符
改为读 `$REDTEAM_VPS_HOST`（同时新增一段配置加载说明），这样同一份技能既能随包公开、又能在配好的机器上直接跑。

## 三、首次使用引导（本次的重点）

### 3.1 一键铺环境脚本：`scripts/redteam-setup.sh`

```sh
bash "$DSH_HOME/redteam/setup.sh" --check   # 体检，10 秒
bash "$DSH_HOME/redteam/setup.sh"           # 交互式：缺啥装啥 + 引导填 key/VPS
bash "$DSH_HOME/redteam/setup.sh" --yes     # 全自动
```

设计原则：**幂等**（随时重跑，`--force` 才重下）、**零依赖**（只用 curl/python3/tar/unzip）、
**不动系统**（只写 `$DSH_HOME/redteam/toolkit/` 与 `$DSH_HOME/.env`，不擅自 `sudo apt`）、
**不静默失败**（每步给结论，最后出体检表）。

它做四件事：① 装工具 ② 体检 nuclei 模板库 ③ 收配置（FOFA_KEY、VPS 地址与私钥） ④ 实测通道并写完成标记 `.setup-complete`。

### 3.2 `redteam_preflight` 新增 `onboarding` 字段

```jsonc
{
  "onboarding": {
    "complete": false,
    "first_run": true,
    "missing": ["FOFA_KEY（资产测绘：…）", "VPS 登录方式（反弹 Shell 落地与载荷投递：…）"],
    "configured": { "fofa_key": "configured(6c72…06f8)", "vps_key": "configured(…)", "vps_host": "…" }
  },
  "next": "**首次使用**：先加载技能 `redteam-setup`，然后执行 `bash …/setup.sh --check` …"
}
```

指挥智能体的第一个动作就是 `redteam_preflight`，因此**首次使用时会自动进入引导**：
把缺口一次性列给用户（要什么、为什么、给到哪），等补齐后再开工——而不是等真正动手时才发现缺 key 缺 VPS。

### 3.3 预检现在会读 `$DSH_HOME/.env`

此前只查 `process.env`，用户按 README 把 `FOFA_KEY` 写进 `$DSH_HOME/.env` 后，
面板与预检仍报"缺 key"（dsh web 启动时才加载那个文件，运行中的进程环境里没有）。
现在预检合并两个来源（进程环境优先、`.env` 兜底），与真实可用性一致。

### 3.4 占位符判定改为"先看配置、再看占位符"

技能正文里的 `<你的VPS_IP>` 原本一律判为"环境没配"——在**已经配好 VPS 的机器上**，
`fscan-intranet` / `gogo-intranet` / `vps-reverse-shell` 会永远显示 broken。
现在只要 `REDTEAM_VPS_HOST` 有值，占位符就只是文档写法，不再算缺口。

## 四之二、安装脚本的三层完整性校验（本轮补强）

首次实现时踩到一个**静默损坏**的坑，值得记下来：

> `gowitness` 下载被截断（本地 43,112,384 字节，官方 50,479,264 字节，**少 7MB**）。
> 它文件存在、可执行位正常、`file` 也认得出是 ELF，但**运行起来零输出零产物、退出码 0**——
> 光看"文件在不在、能不能执行"完全发现不了。

因此 `setup.sh` 现在是三层校验：

1. **下载字节数对账**：`curl` 后与 GitHub API 声明的 `size` 逐字节比对，不符即删除并报错（`--fail` 也会捕获 HTTP 层失败）；
2. **解压后冒烟**：`untar_all` 解出的二进制真跑一次 `--version/-version/-h/--help/version`；
3. **体检表冒烟**：最终体检从"有可执行位"升级为"真能跑起来"，不通过的单独列进 `WEAK` 并给出修复建议。

**自愈语义**（这是关键修正）：先前脚本在体检失败时提示"重跑本脚本加 --force 重下"，
但 `--force` 只对"文件不存在"的下载生效，并不会重下已存在的坏文件 —— **提示与行为不一致，用户照做也修不好**。
现在装了 `doctor()`：**安装前先验，坏文件直接删掉再走下载分支**，所以普通重跑一次即自愈。

已在真实故障上验证：人为把 `gowitness` 截断回 43,112,384 字节 → 普通 `setup.sh --yes` →
自动识别"已损坏或截断" → 删除 → 重下 → 字节数一致 → 冒烟通过。

## 四之三、安装脚本随包分发（市场包用户拿得到）

市场包用户装完只有 `node_modules`，**仓库不在盘上**。而预检原本提示"从仓库取 `scripts/redteam-setup.sh`"——
用户根本拿不到脚本，首次引导在这里就断了。

现在 `build.mjs` 把脚本打进包内 `scripts/`，插件启动时由 `installSetupScript()` 落到
`$DSH_HOME/redteam/setup.sh`（0755，幂等：内容一致不动、不一致自动对齐）。
部署脚本 `deploy-local.mjs` 的同步清单也从 `['presets','skills']` 扩到 `['presets','skills','scripts']`。

已在"全新机器"（空 `DSH_HOME`）上端到端验证：插件启动 → 预设与脚本双双落地（755）→
预检识别 `first_run=true` / `complete=false` → 列出缺 `FOFA_KEY` 与 VPS → 指向 `setup.sh` 与 `redteam-setup` 技能 → 给出降级方案。

## 六、升级注意

1. 装了市场包的机器：`dsh plugin --profile web add dsh-redteam-mode` 升级后，**重启一次 dsh web**；
2. 已有环境**不需要**重跑 `setup.sh`——`redteam_preflight` 会告诉你还缺什么；
3. 想体验首次引导流程：删掉 `$DSH_HOME/redteam/.setup-complete` 再进红队模式；
4. 提示词有历史指纹保护：老靶标里残留的旧提示词不会被自动覆盖，要一次性换新版用 `scripts/refresh-all-prompts.mjs --force`。
