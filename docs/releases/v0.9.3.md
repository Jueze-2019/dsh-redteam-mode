# v0.9.3 — 账号/数据库权限按服务封顶 · 敏感信息量级门槛 · 未读红点 · 安静汇报

## 一、账号权限与数据库权限按「服务」封顶

得分规则修正：**同一个资产的同一个端口只算一次分**。拿到**最高权限账号即该服务拿满**，不需要（也不再允许）在同一个服务上刷多个账号凑分——数据库权限同口径。

| 场景 | 之前 | 现在 |
| --- | --- | --- |
| `10.1.2.3:8080` 上刷 3 个普通账号 | 10 × 3 = 30 分 | **10 分**（一个服务只算一次） |
| 先拿普通账号（10），后拿管理员（20） | 10 + 20 = 30 分 | **20 分**（同服务取分值最高的那条，普通账号那条转为不计分） |
| `10.1.2.3:8080` 的管理员 + `10.1.2.3:9090` 的普通账号 | 30 分 | **30 分**（不同端口 = 不同服务，各算一次） |
| `10.1.2.3:3306` 刷两个库账号 | 25 × 2 = 50 分 | **25 分**；换 `6379` 才另算 |
| 同一服务两个 WebShell / 多次敏感数据导出 | 累加 | **仍然累加**（不设上限的得分点不受影响） |

## 怎么实现的

- **判定只有一份实现**：`applyServiceCap()`（`packages/redteam-store/lib/core.js`）。得分面板 `listScorePoints`、攻击链 `scoreChain`、报告 `scoreReport`、记分返回值 `addScoreHit` 全部走它，四处口径一致。
- **封顶分组**：`web-account-user` / `web-account-admin` 算**同一组**（争同一个名额），`db-access` 单独一组；其余得分点不封顶。
- **服务粒度**：`scoreServiceKey()` 以**目标里的 host[:port]** 为准（`http://h:8080/a/b?c=1` 与 `http://h:8080/other` 是同一个服务；`https://h/x` 按 443 归一，避免同一服务两种写法被算两次）；目标是域名/主机名（不带端口）时按该名字归并；完全没有 target 才退到资产（`a<asset_id>:<port>`，没有端口记 `a<asset_id>:0`）。`score_hit` 新增 `port` 列（端口来源：工具传的 `port` → target 里的端口 → 该资产唯一登记的端口，**不猜 80/443**），老库打开靶标时按 target 回填一次。
- **口径一致的输出**：被封顶的命中 `counted=false`，只作过程留痕；得分面板/攻击链/报告分别给出 `serviceCappedHits` / `serviceCappedExcluded` 计数，报告正文不含它们（抬头说明剔除了多少条）。
- **不让智能体误判"又加了分"**：`redteam_score_hit` 与 `redteam_chain_add` 在命中被封顶时**直接返回 warning**（哪个服务已拿满、计分的是哪一条），提示词「记分纪律」同步写入这条规则，并把「别在同个服务上刷账号」写成停止信号。
- **界面**：得分目标页签把重复命中标黄「服务已拿满 · 不计分（服务标签）」，攻击链里这类命中显示 `+0`；面板顶部单独计数。

## 升级

- 无破坏性改动，老靶标数据不动：新列按库懒加载补齐，端口按 `target` 回填。
- **已有靶标的已记分数会按新规则重算**（同一个服务上的重复命中不再计入总分）——这是规则变化本身，不是数据丢失：重复命中仍留在命中记录里，标为「服务已拿满 · 不计分」。
- 要让提示词生效记得重启一次 `dsh web`（host 侧改动需要重启）。

## 二、「大量敏感信息」量级门槛：≥ 100 万条/行

- `redteam_score_hit` 记 `sensitive-data` 时会解析 `evidence` 里的数据量（`parseRowCount()`，认「120 万条」「1,200,000 条记录」「2.5万行」「1200000 records」，**裸数字不认**，免得把口令里的 `123456` 当数据量）：
  - 低于 1,000,000 → 返回 warning「没到门槛，这不算大量」；
  - 解析不出条数 → 返回 warning「看不出数据量，请写明实际导出量」；
  - 达标 → 正常计分。
- 得分点说明（面板可见）与提示词「记分纪律」同步写入门槛；`redteam_score_hit` 描述新增「红线四」。

## 三、控制台每个页签的未读红点

- host 新增轻量 op `consoleDigest`：每个页签给一个「条数 + 最近更新时间」指针（资产/测试状态/智能体/会话隧道/漏洞/攻击链/得分/报告/攻击文件/知识库）。
- 面板每 25 秒取一次，跟**本机 localStorage 里记住的上次查看状态**比：条数变多或最新一条更新 → 该页签点红点；**点开该页签即记为已读，红点消失**。
- 第一次打开某个靶标时以当前状态为"已读起点"，不会一进来满屏红点；随包分发的静态页签（智能体提示词 / 技能库）永不点红点。

## 四、主会话只在有增量时汇报（省 token）

预设人设新增「什么时候才跟用户说话」：**只有** ①拿到分 ②发现新资产/新入口 ③需要用户出手（缺 key/VPS/账号/范围）或真实卡点 ④阶段推进/硬失败 才发消息，且只写增量、同一批成果只报一次；没有新东西就安静继续派活。用户主动问进度时照常完整回答。

## 五、技能 key 的落地位置：`$DSH_HOME/.env`

- dsh 启动时会读 `$DSH_HOME/.env`（不覆盖已继承的环境变量），`scripts/restart-dsh-web.sh` 也 source 它；
  于是 `FOFA_KEY` 这类 **技能 key 放一次就长期生效**，不必每次重启前手动 export。
- 文件含明文密钥，权限保持 `600`；`redteam_preflight` / 面板技能库的提示语已改为「export 或写进 `$DSH_HOME/.env` 后重启 dsh web」。
