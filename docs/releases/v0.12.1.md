# v0.12.1 — 修复：DSH 0.1.7+ 新会话里选不到「红队模式」

> 主题：**只修模式入口**。资产库、控制台、工具、技能本来就都正常，
> 但 DSH 升到 0.1.7 之后，「红队模式」从新会话的模式列表里消失了。

## 一、根因：agent preset 不再扫目录了

DSH **0.1.7-alpha.1** 起换了 preset 机制：

- 旧机制（`@deepseek-ai/dsh-agent-presets`，止于 **0.1.6-alpha.2**）：扫
  `$DSH_HOME/.agent-presets/<id>/` 目录，所以本插件首次启动会把自带的
  `红队模式` 预设"落地"到那个目录；
- 新机制（`@deepseek-ai/dsh-agent-preset-registry`，0.1.7-alpha.1 起）：**既不扫目录、
  也不接受预设路径**，只认 bundle 补丁里的 `@deepseek-ai/dsh-agent-preset` 声明行。

于是插件照常挂载（`POST /redteam/api` 正常、资产库正常、技能正常），
但那份目录预设成了没人读的死文件 —— 模式列表里只剩内置的
标准 / PTC / 极简 / 创造四个模式。

**本版把预设改成声明行**：`cordis.patch.yml` 的生成区里多了一条 `preset-redteam`，
由 `tools/build.mjs` 从 `preset/` 源码生成，并带 `--check` 漂移检测（改了预设忘记重新生成会被拦住）。

## 二、技能目录改成运行时解析

声明行是静态 YAML，没法再靠"安装时替换 `{{REDTEAM_SKILLS_DIR}}` 占位符"。现在技能目录
在运行时解析：

1. 优先用本插件 host 半侧提供的 `redteamMode` 服务（它用 `import.meta.url` 定位包内路径，
   包搬到哪都对：npx 缓存换 hash、profile 重装、软链开发态都可以）；
2. 兜底按 profile 解析本包。

两条都拿不到时宁可让 `skill-filesystem` 校验报错（预设激活失败、模式列表里带诊断），
也不写死绝对路径 —— v0.9.0 的占位符事故就是这么来的。

技能根顺序不变：`$DSH_HOME/skills` 在前、包内 `skills/` 在后，你在自己那份里配的
VPS 地址 / 密钥仍然优先。

## 三、修掉一个已下线的基座包名

预设里委派用的 `@deepseek-ai/dsh-workflow-worker-thread` 已从 DSH 下线，现在随基座分发的
是 `@deepseek-ai/dsh-workflow-ptc`（同为 `provider: spawn`）。已改名，否则那一行会激活失败。

## 四、兼容性与迁移（重要）

| 你的 DSH | 本版行为 |
| --- | --- |
| ≥ 0.1.7-alpha.1 | 模式列表里出现「红队模式」，**这就是本版修的东西** |
| ≤ 0.1.6 | 照旧：仍走 `$DSH_HOME/.agent-presets/` 目录预设，功能不受影响（日志里会多一条 `preset-redteam ... failed to import` 警告，正常） |

- **补丁层刻意保持单文件**（`dsh.bundle.patch` 不写成数组）：数组形式只有 DSH ≥0.1.7 认，
  0.1.6 及更早会拿数组去 `path.join` 直接抛错、**整个 harness 起不来**。写成单文件后，
  最坏情况也只是那条声明行 import 失败（非致命警告）。
- 目录预设 `presets/redteam/` **仍然随包分发并刷新**，专门留给旧版 DSH。
- 开发态部署脚本 `scripts/deploy-local.mjs` 现在连 `cordis.patch.yml` 与 `package.json`
  一起同步 —— 只同步 `lib/` 会出现"代码是新的、模式列表里还是没有红队模式"。

## 升级

```sh
dsh plugin --profile web add dsh-redteam-mode      # 或 update
```

装完**重启一次 `dsh web`**（bundle 清单在启动时读），新会话里就能选到「红队模式」。

已有靶局的事实库、得分记录、报告、已配好的技能目录**都不受影响**，不需要任何迁移动作。
