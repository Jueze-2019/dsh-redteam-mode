# v0.11.3 — 对齐《得分规则（合并版）》、报告可复现、技能库可观

> 主题：**记分口径与规则文档对齐，报告做到"每一步都能复现"**。
> 本版把旧得分项整套换成《突破入侵类得分规则（合并版）》的 8 类 25 项，并把
> "为什么算 / 为什么不算"变成服务端可判定的硬规则；同时补齐技能库可用性判定与报告溯源链。

## 一、得分规则换成《合并版》，口径由服务端判定

旧得分项（`web-account-*` / `webshell` / `rce` / `server-shell` / `db-access` /
`sensitive-data` / `boundary` / `internal-pivot` / `core-system`）整套作废，
换成按《突破入侵类得分规则（合并版）》锁定的 8 个类别、25 个得分点：

| 类别 | 代表条目 | 口径 |
| --- | --- | --- |
| 控制一般系统 | 域名控制、终端权限、服务器主机权限、数据库账号 | `system` / 按台累加 |
| 控制 Web 应用系统 | 邮箱系统 / OA / 业务生产系统 | `system` |
| 控制集权系统 | 运维 / 身份 / 组网 / 终端管理后台 | `system` |
| 控制大数据系统 | 大数据系统权限 | `system` |
| 控制网络基础设施 | 网络设备、工控、云平台、物联网、安全设备 | `service` / `none` |
| 文件存储类系统 | FTP / 对象存储 / NAS / 网盘 | `system` |
| 控制模型相关系统 | 模型智能体与 skill、算力平台、训练数据、算力卡 | `system` / 按卡累加 |
| 突破网络边界 | 逻辑隔离 / 强隔离 / 物理隔离 / 供应链通道 | `target` |

**四条硬规则**（不再靠自觉，服务端直接判定并在返回值里说明原因）：

- **累计上限**：同一 rule 的命中按分值从高到低累计，超出上限的部分标「不计分」只留痕；
- **权限取高、只计一次**（G1）：同一服务 / 同一系统上先记的普通权限会被管理员权限顶掉；
- **同一服务只算一次**：账号权限与数据库权限按「同一资产 + 同一端口」封顶，
  刷多个账号凑分会被拒（`scoreServiceKey` / `applyScoreCaps`）；
- **自建账号不计分**：自助注册的账号 `self_created=true` 留痕，不计分、不占上限、不进报告。

内置得分点的分值 / 上限 / 口径 / 条款正文随规则锁定，面板里置灰不可改；要自定义分值只能**新增**得分点。

**历史数据迁移**：旧口径的命中不会自己消失，用两个脚本按新规则重新归类（先 dry-run）：

```sh
node scripts/migrate-legacy-scores.mjs            # 列出每个靶标将迁移多少条
node scripts/migrate-legacy-scores.mjs --apply    # 执行
node scripts/restore-legacy-hits.mjs <靶标> [--apply]   # 从 runs/legacy-score-*.json 存档写回
```

## 二、报告做到"每条成果都能复现"

报告页签按阶段可折叠，只收录得分成果，**每条附可粘进 Yakit 的原始请求**，并强制给出
「这一步怎么来的」：

- **动作步骤**：谁做的、为什么、**实际命令**、回显；
- **凭据来源**：账号密码是怎么来的；
- **隧道搭建命令**：隧道怎么搭的；
- **WebShell 连接要素**：马的类型、地址、口令获取方式。

缺步骤或缺命令的条目会被标 **「复现链不完整」并列出缺口**，而不是悄悄放过。
自建账号与「同服务重复命中」整条剔除，抬头分别给出剔除了多少条。
文末附**资产发现时间**附录（第一次入库的时刻；重复采集只刷新「最近采集」）。

## 三、技能库：从"列出来"到"能不能用"

技能页签给每个技能标出 **可用性状态**（可用 / 不可用 / 未知），判定维度客观可查：
技能文件存在 → 正文能加载 → 必需环境变量已设（`$DSH_HOME/.env` 也算数）→
正文引用的本机路径存在 → 没有未填的基础设施占位符。

同一份判定逻辑（`skill-availability.js`）同时供**面板**与 `redteam_preflight` 使用，
所以"面板说不可用"和"预检报 broken"永远一致；缺口会直接点名（缺哪个 key、缺哪个二进制、
VPS 还是占位符），可「只看不可用 / 未知」与「重查可用性」。

## 五、修掉两个"发出去才会发现"的问题

1. **安装脚本没随 npm 包发布**：`build.mjs` 一直把 `scripts/redteam-setup.sh` 生成进
   `packages/redteam-bundle/scripts/`，插件启动也一直调用 `installSetupScript()` 把它落到
   `$DSH_HOME/redteam/setup.sh` —— 但 `package.json` 的 `files` 字段没有 `scripts`，
   **npm 打包时把它排除了**（核实过 0.9.2 的 tarball：0 个 `scripts/` 文件）。
   于是市场包用户启动时拿到的是 `action: 'missing'`，首次引导在"跑 setup.sh"这一步断掉。
   本版把 `scripts` 加进 `files`，`npm pack` 后 `scripts/redteam-setup.sh` 已在包内。
2. **公开源码里夹带真实客户内网地址**：`schema.js` / `score-rules.js` 的注释示例用了
   某靶标的内网 IP，随源码与 npm 包一起公开。发布前扫描发现后**替换为文档保留网段
   `10.20.30.40`**（RFC 5737 风格写法）；演练现场产物（靶标资产清单、隧道配置、
   留证截图、可达性探测脚本）已列为**仓库根忽略项**，只留在本机。

## 七、关于版本号与双用途声明

本版对外的 npm 版本号是 **0.11.3**（GitHub 标签 `v0.11.1`，代码内容一致）。

排查历程值得记一笔：`0.11.0` / `0.11.1` / `0.11.2` 三次 `npm publish` 都打印成功，
但版本一直停在 npm 的 `Validating`（校验中）状态，既查不到也装不上。根因是 npm 2026-07 起的
**发布期恶意代码扫描 + 双用途内容政策**：本包编排扫描器、会话工具与反弹 Shell 技能，
属于政策定义的 dual-use 内容，**未声明就会被扣下人工复核**。政策要求两件事：

1. `package.json` 里加 `"contentPolicy": { "class": "dual-use" }`；
2. 包根放一个 `DISCLOSURE` 文件，说明双用途能力与合法用途。

两者本版都已加上（`DISCLOSURE` 已确认进包）。另外政策规定：**声明了双用途的包必须用
强制 2FA 的方式发布**（受信发布 OIDC / 带验证码的交互式会话 / 暂存后批准），
绕过 2FA 的 token 只能发到暂存。详见 `docs/marketplace.md`。

## 八、升级注意

1. 装了市场包的机器：`dsh plugin --profile web add dsh-redteam-mode` 升级后**重启一次 `dsh web`**
   （host 平面有新增服务与表结构；客户端 UI 改动会自动热重载）；
2. 本版**换了整套得分点**：老靶标库里的旧命中不会自动转换，按需跑第一节的两个迁移脚本（先 `dry-run`）；
3. 提示词有历史指纹保护：老靶标里残留的旧提示词不会被自动覆盖，要一次性换新版用
   `node scripts/refresh-all-prompts.mjs --force`（覆盖前自动 `.bak` 备份）。
