# v0.13.2 — 适配 DSH 0.2.1：子智能体改用独立执行角色预设

## 解决了什么问题

升级到 **DSH 0.2.1-rc.2** 后，启动日志会出现：

```
tool-subagent: toolFilter is no longer supported; configure persona and tool plugins
in an Agent Preset and select it with agentPreset (spawn only)
```

随后 `agent-preset-registry` 报：

```
agent preset redteam: tool-subagent (@deepseek-ai/dsh-tool-subagent): ...
```

结果是**红队预设里的 `subagent` 委派工具不注册**——主会话没法再派执行智能体
（资产库、控制台、技能、其它工具都不受影响）。

原因：DSH 0.2.1 从 `@deepseek-ai/dsh-tool-subagent` 移除了 `toolFilter` / `persona`
两个配置字段，`apply()` 遇到它们直接抛错。红队预设还写着：

```yaml
toolFilter:
  deny: [subagent_fork, workflow, ralph]
```

## 本版改动

- **新增执行角色预设 `redteam-worker`**（源码 `preset/worker.cordis.yml`）：
  只挂执行侧工具（shell / fs / jobs / 技能 / web / `redteam_*`），**不挂任何委派工具**
  ——`subagent` / `subagent_fork` / `workflow` / `ralph` 一个都没有，子智能体连看都看不到。
  人设是"执行者"：具体角色职责由主会话用 `redteam_role_prompt` 取出、写进任务描述。
- **主预设改用 `agentPreset`**：`tool-subagent` 行删掉 `toolFilter`，改成
  `agentPreset: redteam-worker`；`maxDepth: 1` 保留作二道保险。
- **`cordis.patch.yml` 生成两条声明行**：`preset-redteam`（指挥者）与
  `preset-redteam-worker`（执行角色），由 `tools/build.mjs` 从 `preset/` 生成。
- **回归测试更新**：锁住"主预设不再出现 `toolFilter` / `persona` 配置键"、
  "执行角色预设不引用任何 `dsh-tool-subagent` / workflow / ralph 行"、
  "`agentPreset` 指向 `redteam-worker`"。
- **控制台 Markdown 渲染**：面板里的提示文案、角色提示词、技能正文、模型回报/证据
  本身都是 Markdown，以前按纯文本显示，用户会看到满屏 `**`、反引号和 `##`。现在统一
  走安全的行内/块级渲染（标题 / 列表 / 表格 / 引用 / 围栏代码 / 粗体 / 行内代码）；
  角色提示词默认显示渲染预览、点「编辑」切回 Markdown 源文；技能正文与 `.md` 攻击文件
  按 Markdown 渲染，原始 HTTP 报文与命令仍逐字显示（不会被当成 Markdown）。

## 兼容性

| 你的 DSH | 升级到本版后 |
| --- | --- |
| 0.2.1 及以上 | 委派工具正常注册，子智能体使用执行角色预设（本版修复的目标） |
| 0.1.7–0.2.0 | 仍可加载；旧版不认识 `agentPreset`，会忽略它，叶子约束只剩 `maxDepth: 1` |
| 0.1.6 及更低 | 仍走 `$DSH_HOME/.agent-presets/` 目录预设，行为与之前一致 |

> 执行角色预设也会出现在新会话的模式列表里（DSH 的 preset 声明没有"隐藏"标记）。
> 它的显示名/描述已写明"由红队主会话自动选用，请不要手动选择"。

## 升级

```sh
dsh plugin --profile web add dsh-redteam-mode      # 或 update
```

装完**重启一次 `dsh web`**。已有靶局的事实库、得分记录、报告、技能目录都不受影响。
